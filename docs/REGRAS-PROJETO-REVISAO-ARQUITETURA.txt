2.1) REGRA A - AGENTS.md

Origem:
- Arquivo: AGENTS.md
- Escopo: instrucoes operacionais de desenvolvimento e execucao local.

Diretrizes principais:
- Aplicacao Next.js PWA; interface em portugues.
- Backend Firebase (Auth, Firestore, Storage), config em src/firebase/config.ts.
- Comandos padrao:
  - npm run dev (porta 9002, host 0.0.0.0)
  - npm run dev:turbo
  - npm run build
  - npm run lint
  - npm run typecheck
  - npm run deploy:rules
- Sem emuladores; dados em nuvem.
- Regras Firestore:
  - unico ficheiro de deploy: src/firebase/rules/firestore.rules (via firebase.json); sem espelhos em src/ ou raiz
- build executa postbuild com deploy:rules.
- Acesso celular por IP da maquina + porta 9002.

Impacto arquitetural:
- Padroniza execucao e reproducibilidade.
- Acopla build local a deploy de regras.
- Mantem estrategia cloud-first.
- Vincula comportamento de autorizacao a regras publicadas.

Riscos:
- Publicacao nao intencional de regras em build local.
- Dependencia alta de credenciais e ambiente cloud.
- Manter uma unica fonte de regras (firebase/rules) evita divergencia face ao deploy.

2.2) REGRA B - .cursor/rules/ambientar-firebase-e-deploy.mdc

Origem:
- Arquivo: .cursor/rules/ambientar-firebase-e-deploy.mdc
- Tipo: alwaysApply: true
- Escopo: repositorio x nuvem Firebase, deploy e producao.

Diretrizes principais:
- Repositorio local/GitHub contem codigo e docs.
- Firebase recebe apenas o que for publicado via deploy.
- Projeto alvo: studio-316805764-e4d13.
- Regras Firestore de deploy: src/firebase/rules/firestore.rules via firebase.json.
- Fluxo local recomendado:
  - npm install
  - npm run dev / npm run dev:turbo
  - npm run deploy:rules
- Pos-Blaze: checklist de Auth/Firestore/Storage/Functions/roles.
- Producao:
  - firebase deploy --only hosting publica apenas estaticos (public/)
  - Next completo deve usar App Hosting, Vercel ou Cloud Run
- Windows (E:\AmbientaR): pode requerer git config --global --add safe.directory E:/AmbientaR (ajustar ao caminho real)

Impacto arquitetural:
- Delimita fronteira entre codigo versionado e estado da nuvem.
- Define estrategia de deploy granular por componente.
- Alinha escolha de hospedagem com limites de hosting estatico.

Riscos:
- Confundir hosting estatico com deploy completo de app Next (SSR/API).
- Regras de Storage fora do pipeline se bloco storage nao existir no firebase.json.
- Roles em users/{uid} sao precondicao para autorizacao correta.
